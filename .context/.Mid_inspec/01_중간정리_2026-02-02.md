## 1. 프로젝트 개요 및 현재 상태

### 1.1 목표(초기 설계 기준)
- 개인 문서 기반 질의응답 AI 비서 구축
- 기술 스택: FastAPI + LangGraph + Chroma + SQLite + OpenAI
- 개발 순서: Bootstrap → Storage → Graph → API → Ingestion → CLI → 품질안정화
- MVP 클라이언트: CLI, 향후 Web 확장

### 1.2 현재 상태(요약)
- **핵심 구현 완료**: API/Graph/Ingestion/CLI/로그/리랭커/토큰 청킹/OCR
- **운영 안정화 완료**: 평가 자동화, 배치 실행, auto-port, 실패 요약, soak 자동화
- **품질 관측 고도화 완료**: 분석기(실패 유형/소스 분포/드리프트) + 경고 임계치/exit code 게이트

## 2. 아키텍처/핵심 컴포넌트 현황

### 2.1 서버/API 계층
- 엔트리: `rag_assistant/app/main.py`
- 라우트:
  - `/health`
  - `/chat`
  - `/ingest`
  - `/threads`
  - `/threads/reset`
- 응답 포맷: `success/data/error` 공통 구조

### 2.2 LangGraph 계층
- 그래프: `route -> retrieve -> generate -> finalize`
- 상태 관리: `State` 기반(JSON checkpoint 저장)
- 타이밍 메트릭:
  - `t_route_ms`, `t_retrieve_ms`, `t_generate_ms`, `t_finalize_ms`, `t_total_ms`
- 토큰 메트릭:
  - `prompt/completion/total`

### 2.3 저장소 계층
- Vector DB: Chroma(persistent)
- Docstore: SQLite
- Checkpoint: SQLite
- 인제스트 중복 정책:
  - `source_path + content_hash` 동일 시 skip
  - 변경 시 기존 문서/벡터 삭제 후 재저장

## 3. 인제스트/검색/생성 기능 진화 이력

### 3.1 인제스트 파이프라인
- 단계 구현:
  - discovery → parse → clean → chunk → metadata → embed → store
- 지원 형식:
  - `.txt`, `.md`, `.pdf`, `.docx`
- 청킹:
  - 초기 문자기반 -> **토큰기반(tiktoken) 전환 완료**
- OCR:
  - PDF 텍스트 추출 저품질 시 OCR fallback
  - 설정: `OCR_ENABLED`, `OCR_LANG`, `OCR_DPI`, `OCR_MAX_PAGES`, `OCR_MIN_TEXT_LEN`

### 3.2 검색/리랭커
- 기본 검색: Chroma top_k
- 리랭커 모드:
  - `off | auto | always`
- 튜닝 이력:
  - distance threshold 스윕/세분화 수행
  - 최종 기본값: `RERANKER_DISTANCE_THRESHOLD=0.6`

### 3.3 생성 노드 개선
- system 지시 강화:
  - 제공 컨텍스트 기반 답변 강제
  - 근거 없으면 모른다고 답하도록 제한
- context 구성 개선:
  - source 라벨 포함
  - 길이 제한 적용

## 4. 평가 체계 구축/고도화 이력 (핵심)

### 4.1 고정 평가셋 도입
- 평가 전용 문서:
  - `rag_assistant/evals/docs/rag_overview.txt`
  - `rag_assistant/evals/docs/ingestion_notes.txt`
  - `rag_assistant/evals/docs/reranker_policy.txt`
- 평가 케이스:
  - `rag_assistant/evals/e2e_eval_cases.jsonl`
  - 12 -> 36케이스 확장 완료

### 4.2 E2E 자동 평가 스크립트
- 파일: `rag_assistant/scripts/e2e_eval.py`
- 기능:
  - 인제스트(옵션) + `/chat` 반복 호출
  - keyword/citation/latency 지표 수집
  - JSON 리포트 출력
- 확장:
  - 재시도(backoff) 추가
  - 케이스 범위 실행(`--start-index`, `--end-index`)
  - detail에 `citation_source_paths` 추가

### 4.3 배치 러너(안정 실행)
- 파일: `rag_assistant/scripts/e2e_eval_batch_runner.py`
- 기능:
  - 배치 단위 서버 재기동
  - 배치 결과 자동 병합
  - auto-port
  - 서버 로그 저장(`--server-log-dir`)
  - 실패 요약(`--failure-summary-path`, `--failure-tail-lines`)

### 4.4 soak 러너(장시간 안정성 자동화)
- 파일: `rag_assistant/scripts/e2e_soak_runner.py`
- 기능:
  - batch runner를 사이클 반복 실행
  - 누적 성공률/정확도/지연 통계
  - 사이클 실패 정보 수집

### 4.5 리포트 분석기(관측 고도화)
- 파일: `rag_assistant/scripts/e2e_report_analyzer.py`
- 기능:
  - E2E/Soak 리포트 자동 분석
  - 실패 유형 분류
  - top errors
  - source_path 분포
  - soak drift 탐지
  - 임계치 기반 alerts + `--fail-on-alert`(exit code 2)

## 6. “서버 끊김” 이슈 중간 결론

### 6.1 관찰
- 과거 ad-hoc PowerShell `Start-Process` 흐름에서 간헐적 연결 끊김 발생
- 앱 로그에서 일관된 traceback/critical 패턴은 명확하지 않음

### 6.2 검증
- 단일 서버 연속 호출(40회)에서 리소스 누수/즉시 크래시 재현되지 않음
- batch runner 경로에서 36케이스 단일 배치 및 다배치 실행 모두 안정

### 6.3 중간 결론
- 앱 로직보다는 **실행 하네스/프로세스 관리 방식 영향** 가능성이 높음
- 운영 표준 경로를 batch/soak runner로 통일하는 것이 현재 최적

## 8. 현재 운영 표준 명령(권장)

### 8.1 전체 E2E 배치 검증(36)
```powershell
cd D:\ProjectRAG\rag_assistant
.\.venv\Scripts\python.exe .\scripts\e2e_eval_batch_runner.py `
  --cases .\evals\e2e_eval_cases.jsonl `
  --ingest-path .\evals\docs `
  --batch-size 12 `
  --api-host 127.0.0.1 `
  --api-port 8074 `
  --auto-port `
  --thread-prefix eval-main `
  --max-retries 2 `
  --retry-backoff-sec 1.0 `
  --server-log-dir .\evals\results\server_logs `
  --failure-summary-path .\evals\results\e2e_eval_failure_summary.json `
  --failure-tail-lines 20 `
  --output .\evals\results\e2e_eval_full.json
```

### 8.2 soak(장시간) 검증(144)
```powershell
cd D:\ProjectRAG\rag_assistant
.\.venv\Scripts\python.exe .\scripts\e2e_soak_runner.py `
  --cycles 4 `
  --cases .\evals\e2e_eval_cases.jsonl `
  --ingest-path .\evals\docs `
  --batch-size 12 `
  --api-host 127.0.0.1 `
  --api-port 8080 `
  --auto-port `
  --thread-prefix soak-main `
  --max-retries 2 `
  --retry-backoff-sec 1.0 `
  --skip-ingest-after-first `
  --output-dir .\evals\results\soak `
  --output .\evals\results\e2e_soak_144.json
```

### 8.3 분석 + 경고 게이트
