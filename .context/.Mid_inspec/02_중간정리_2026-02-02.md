## 2. 현재 기능 상태 (요약)

### 2.1 API/그래프
- 핵심 API: `/health`, `/chat`, `/ingest`, `/threads`, `/threads/reset`
- 그래프 흐름: `route -> retrieve -> generate -> finalize`
- 응답 메타: tokens, timing 포함

### 2.2 데이터 저장소
- Vector DB: Chroma
- Docstore: SQLite
- Checkpoint: SQLite
- 중복 인제스트 정책:
  - `source_path + content_hash` 동일 시 스킵
  - 변경 시 기존 청크/벡터 삭제 후 재저장

### 2.3 인제스트 지원 포맷
- 문서: `txt`, `md`, `pdf`, `docx`
- 이미지 OCR: `png`, `jpg`, `jpeg`, `webp`, `bmp`, `tif`, `tiff`
- OCR 설정: `.env`의 `OCR_ENABLED`, `OCR_LANG`, `OCR_DPI` 등 사용

### 2.4 클라이언트
- CLI 사용 가능
- Web UI(`/web`) 사용 가능:
  - 질문/답변/출처 확인
  - 저장 스레드 조회/초기화
  - 인제스트 실행

## 3. Web UI 개선 사항 상세

### 3.1 UX 개선
- `thread_id` 직접 입력을 고급 설정(details)으로 이동
- 기본 사용자는 스레드 선택 + 질문 입력만으로 사용 가능

### 3.2 한글화
- 라벨/버튼/상태/오류 메시지 한국어화
- health 상태 문구, 버튼 텍스트, 안내문, 진행/실패 메시지 정리

### 3.3 운영 흐름
- `/web`에서 `/chat`, `/threads/reset`, `/ingest` 직접 호출 가능
- 결과 영역 초기화/스레드 새로고침/출처 표시 포함

## 4. 이미지 OCR 기능 도입 상태

### 4.1 구현 포인트
- `discovery.py`: 이미지 확장자 탐색 대상 추가
- `loaders.py`: 이미지 파싱 분기 + OCR 비활성 시 안내 오류 처리
- `ocr.py`: `ocr_image()` 추가

### 4.2 동작 특성
- 이미지 텍스트를 OCR로 추출해 문서 청크로 저장
- `/chat` 검색 시 해당 OCR 텍스트 기반으로 retrieval

### 4.3 확인된 한계
- OCR 오인식 가능(숫자/특수문자/밑줄 등)
- 질문 표현이나 top-k 상황에 따라 원하는 이미지가 상위 citation에 항상 노출되지는 않을 수 있음
